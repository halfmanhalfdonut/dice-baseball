# CODE_STATUS

This document tracks the current code status, roadmap, acceptance criteria, estimates, risks, and immediate next steps for the dice-baseball project.

---

## Current state (summary)

- **Engine**: Deterministic RNG, at-bat → advancement pipeline, inning & game simulators, box-score and plate-appearance recording. Fully covered by 71 unit tests across 29 spec files.
- **Advancement scenarios**: Deterministic metadata — `scoredPositions`, `rbiAllowed`, `isSacrifice`, `isFielderChoice`.
- **Test tooling**: Vitest + jsdom. `forceAtBat` API for deterministic end-to-end scenarios. All tests green.
- **UI scaffold** (`app/`): Vite + TypeScript + Lit PWA. Components:
  - `AppShell` — header with hash routing (Home / Game / Settings / Lineups toggle)
  - `SplashPage` — landing page with "Play Ball" button → `#game`
  - `GamePage` → embeds `GameRunner`
  - `GameRunner` — seed/innings controls, Run/Regenerate/Save/Load/Share, inline lineup editors
  - `BoxScore` / `PlayByPlay` — display components
  - `LineupManager` — overlay with save/load/delete/rename, focus trap, `aria-modal`, Escape-to-close
  - `Toast` — feedback notifications
  - `SettingsPage` — basic info display (theme, SW status)
- **Persistence**: PouchDB UMD loaded at runtime via fetch+blob import when available; falls back to `localStorage`. Named-lineup CRUD helpers (`saveNamedLineup`, `listLineups`, `loadNamedLineup`, `deleteLineup`).
- **PWA**: `vite-plugin-pwa` generates Workbox-powered `sw.js` during production build. Precaching + runtime caching strategies configured.
- **Build**: Production build succeeds → `app/dist/` with `sw.js`, `workbox-*.js`, `manifest.webmanifest`, ~18 KB gzipped JS.

## Risks and trade-offs

- Start with a small UI (runner + box) to get quick value and discover UI requirements.
- PWA and persistence add complexity; defer until the UI is stable.
- Heuristics (e.g., isFielderChoice) exist in multiple places; we can consolidate later for clarity.

## Notes for maintainers

- **Tests**: `forceAtBat` and `simulateInning({ forceAtBat })` are the preferred way to write deterministic e2e tests in the `app/src/game` tests.
- **Scoring**: `AdvancementScenario` carries `rbiAllowed`, `isSacrifice`, and `isFielderChoice`; mapping to lineup indices is done in `InningSimulator`.
- **Service worker**: Generated by `vite-plugin-pwa` (see `app/vite.config.ts`). Lives in `app/dist/sw.js` after build. Legacy `sw-workbox.js` and `sw.js` in `src/` are unused artifacts.
- **Runtime imports**: To keep the app buildable inside `app/` while optionally using host-repo helpers (TeamGenerator, PouchDB UMD), those files are fetched dynamically at runtime when present.
